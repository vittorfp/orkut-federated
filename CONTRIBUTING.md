# Contributing

The project is currently in its research and architecture phase. Review and
discussion are more useful than implementation pull requests at this stage.

## Reviewing the initial plan

Please focus feedback on:

- ActivityPub mappings for scraps, testimonials, friendships, albums, and
  communities.
- Bluesky and RSS integration boundaries.
- The public-only privacy model and curated federation policy.
- Moderation, abuse handling, data deletion, and account migration.
- Reusable-code and license assumptions.
- Delivery estimates, operational risks, and missing acceptance tests.

When proposing an architectural change, describe the user-visible benefit,
the interoperability effect, and any new moderation or operational burden.

## Research and attribution concerns

Open an issue or leave a pull-request comment if a cited claim is outdated, a
license is described incorrectly, attribution is missing, or material should
not be reused. Unlicensed and source-available projects must remain
reference-only unless explicit permission is documented.

## Security and privacy

Do not include credentials, production data, personal archives, private user
information, or copied data from the original Orkut service in issues or pull
requests.

Security vulnerabilities should not be disclosed publicly once executable
code exists. A private reporting process will be added before the first
deployed version.
